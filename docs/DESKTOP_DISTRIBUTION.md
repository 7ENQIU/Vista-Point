# Desktop-доставка Vista Point

## Принятое решение

Основное приложение упаковывается в Tauri 2 для Windows x64. Кампании продолжают храниться локально, а обращение к сети выполняется только по явной команде **«Проверить обновления»**. Установщик включает автономный установщик Microsoft WebView2: его размер увеличивается примерно на 127 МБ, зато пользователю не требуется вручную устанавливать среду выполнения.

Основной установочный формат — NSIS `*-setup.exe`. Он устанавливается для текущего пользователя и не требует постоянного запуска Vista Point с правами администратора. Обновление загружается официальным Tauri Updater и принимается только при корректной криптографической подписи.

## Два разных сценария

1. **Первичная установка.** Фирменный bootstrapper показывает доступные выпуски, каталог установки и канал. Он получает только метаданные релизов `7ENQIU/Vista-Point`, затем запускает подписанный NSIS выбранной версии. Bootstrapper не получает доступ к кампаниям.
2. **Обновление установленного приложения.** Главный экран проверяет `latest.json` последнего опубликованного GitHub Release, показывает найденную версию и устанавливает её только после подтверждения пользователя.

Выбор произвольной старой версии нельзя безопасно смешивать с обычным автообновлением: `latest.json` описывает актуальный выпуск, а откат может содержать несовместимый формат локальных данных. Поэтому rollback будет отдельным действием фирменного bootstrapper с обязательной резервной копией и предупреждением о версии схемы.

## Что уже подготовлено

- `src-tauri` — нативная оболочка приложения;
- ограниченная Content Security Policy для локального интерфейса, встроенных изображений и Tauri IPC;
- автономная установка WebView2;
- ручная проверка, загрузка и установка подписанного обновления;
- GitHub Actions workflow, создающий только **черновик** релиза;
- светлая и тёмная темы в одном дизайн-коде;
- широкая desktop-компоновка для 4:3, 16:9 и 21:9.

## Что обязательно сделать перед первым desktop-релизом

1. Проверить наличие **Visual Studio Build Tools 2022** с компонентом **Desktop development with C++** и Windows 10/11 SDK командой `npm exec tauri info`. Без `link.exe` Rust не может собрать Windows-приложение.
2. Не регенерировать уже используемый release-ключ. Для нового проекта выполнить `npm exec tauri signer generate -- -w <безопасный-путь-к-ключу>` и сохранить пароль отдельно.
3. Скопировать содержимое публичного ключа в `plugins.updater.pubkey` файла `src-tauri/tauri.conf.json`. Для Vista Point этот шаг уже выполнен.
4. Сохранить приватный ключ и пароль в GitHub Secrets `TAURI_SIGNING_PRIVATE_KEY` и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Приватный ключ нельзя добавлять в репозиторий; его потеря лишит уже установленные копии возможности безопасно обновляться.
5. Синхронно изменить версию в `package.json`, `package-lock.json`, `src-tauri/Cargo.toml` и `src-tauri/tauri.conf.json`, обновить `CHANGELOG.md`, затем вручную запустить workflow **«Подготовить desktop-релиз»** из проверенного релизного коммита. Workflow отклонит тег, не совпадающий с версией, и создаст тег и черновик релиза из выбранного коммита; публикация остаётся отдельным осознанным действием автора.
6. Проверить установку и обновление на чистой Windows-среде до публикации.

## Фирменный bootstrapper

Полностью фирменный выбор версии не является настройкой стандартного NSIS-интерфейса. Это отдельное небольшое приложение доставки. Его контракт:

- мятно-слоновая светлая и тёмная тема Vista Point;
- список опубликованных версий с поиском и пометками «актуальная», «тестовая», «устаревшая»;
- выбор каталога и создание отдельной папки версии;
- загрузка только HTTPS-ресурсов репозитория `7ENQIU/Vista-Point`;
- проверка подписи до запуска установщика;
- запрет тихого downgrade без резервной копии;
- понятная ошибка без повреждения уже установленной версии.

Для ручной проверки установки подготавливается локальный кандидат `0.2.0`. Опубликованные теги `v0.1.0`–`v0.1.3` не перезаписываются; тег `v0.2.0` и подписанные updater-артефакты создаются только после проверки кандидата. До реализации bootstrapper необходимо проверить установку, получить `latest.json`, проверить подпись обновления и подтвердить сохранность локальных данных.
