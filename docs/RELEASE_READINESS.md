# Готовность к следующему релизу

Проверено 27 августа 2026 года. Документ относится к текущему большому циклу визуального board и не означает, что релиз уже создан или опубликован.

## Что уже проверено

- Версия релиз-кандидата `0.2.0` совпадает в `package.json`, `package-lock.json`, `tauri.conf.json`, `Cargo.toml` и метаданных Windows-приложения.
- `npm run check`: проверка типов, 64 файла тестов и 278 тестов проходят; production-сборка web-интерфейса создаётся успешно.
- Сетевой `npm audit` проверил 115 зависимостей: уязвимостей всех уровней — `0`.
- `cargo audit` проверил 477 записей `Cargo.lock`: уязвимостей, применимых к Windows-сборке, не найдено; 17 разрешённых предупреждений о GTK/glib и не сопровождаемых транзитивных пакетах описаны в документе зависимостей.
- У всех 62 уникальных установленных npm-пакетов указана лицензия; используются MIT, Apache-2.0, BSD-3-Clause, ISC, MPL-2.0 и OFL-1.1 либо их совместимые сочетания.
- Все прежние форматы кампании от схемы `1` до `21` проходят последовательную миграцию в схему `22` и итоговую проверку целостности.
- Экспорт, импорт, локальные страховочные копии и восстановление покрыты автоматическими тестами.
- `cargo check --locked` проходит на зафиксированном наборе Rust-зависимостей.
- Tauri находит WebView2, Rust и инструменты сборки Windows; локальный NSIS-кандидат с автономным WebView2 собран успешно.
- Актуальный локальный установщик `Vista Point_0.2.0_x64-setup.exe`: 218 991 376 байт, SHA-256 `43F24D19E4A35D0E1EABC9CB41078401E0BBF0111581F6A9301B56F800FAD5A6`; выборочная проверка Microsoft Defender угроз не обнаружила.
- GitHub CLI авторизован как `7ENQIU`, а секреты `TAURI_SIGNING_PRIVATE_KEY` и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` настроены для будущей подписанной CI-сборки.
- В web-оболочке вручную проверены граф знаний, граф логики, краткий попап и полная карточка, библиотека, сохранённые виды и журнал событий.
- В графе знаний вручную проверены контраст выбранной карточки, масштабирование колесом без прокрутки страницы, восстановление позиции после полноэкранного режима, настройка `N / Т`, быстрый факт без фокуса и ручная правка маршрута мышью и стрелками.
- Предпросмотр логического результата не изменяет кампанию и ведёт к отдельному подтверждению мастера.
- В release workflow добавлена проверка совпадения версии в теге, `package.json`, `package-lock.json`, `tauri.conf.json` и `Cargo.toml`.
- Desktop-оболочка использует ограниченную Content Security Policy и заголовок `X-Content-Type-Options: nosniff`.

## Обязательные действия перед выпуском

- Вручную проверить установку локального кандидата `0.2.0`, запуск, сохранение данных после перезапуска и удаление приложения.
- После успешной ручной проверки создать релизный commit и запустить GitHub workflow для подписанного NSIS-установщика и updater-артефактов с внешним приватным ключом.
- Проверить чистую установку подписанного файла и обновление с предыдущей версии.
- Просмотреть итоговый diff и повторить проверку отсутствия пользовательских кампаний, секретов и локальных настроек.
- Публиковать подготовленный draft release только после отдельного подтверждения автора.

## Известные ограничения текущего цикла

- Раздел «Сессия» намеренно заморожен и помечен как находящийся в разработке.
- Legacy-данные прежних подсистем сохраняются ради совместимости, но не участвуют в новых рабочих сценариях.
- Свободная раскладка графа хранится локально на устройстве; сохранённые виды переносят запрос и фильтры, а не координаты карточек.
- Bootstrapper пока не является частью release workflow.
- Локальный установочный кандидат не подписан сертификатом издателя и предназначен только для ручной проверки; Windows может показать предупреждение SmartScreen. Хэш будущего подписанного артефакта будет другим.
- Ранее созданный локальный тестовый стенд может хранить старый пользовательский текст карточек. Новый генератор стенда уже не добавляет признаки черновика.
