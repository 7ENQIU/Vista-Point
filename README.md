# Vista Point

Vista Point — локальный визуальный board мастера настольной ролевой игры. Единый канвас соединяет граф знаний и простую предикативную логику.

> **Vista Point** — открытый некоммерческий хоббийный проект для подготовки и ведения настольных ролевых кампаний. Проект развивается автором в формате vibe coding при существенной помощи ИИ-агента OpenAI Codex. Vista Point не является официальным продуктом OpenAI, Wizards of the Coast или других издателей и не предназначен для продажи. Пользовательские игровые материалы принадлежат их соответствующим авторам и правообладателям.

## Текущее состояние

Vista Point переходит к новой продуктовой модели. Основной раздел теперь — единый «Канвас» с переключением между графом знаний и графом логики; на логическом графе можно собирать правила из нескольких условий, проверять типизированные параметры состояния и готовить подтверждаемые изменения статуса или значения. Прежние экраны кампании собраны в «Подробнее», а раздел «Сессия» временно заморожен. Фокус на узле показывает краткий попап, а единая полная карточка открывается поверх графа или библиотеки, поддерживает отдельные заметки ДМа, типизированные пользовательские поля, состояние, входящие и исходящие факты, контекст истории и одно локальное изображение. Из сохранённой карточки можно создать переносимый шаблон и применить его при быстром создании новой уникальной сущности. Сущности связываются фактами через стабильные встроенные или пользовательские предикаты с прямым и обратным названием. Legacy-данные пока сохраняются, чтобы не рисковать существующими проектами. Поэтапная карта перехода описана в [плане визуального board](docs/VISUAL_BOARD_ROADMAP.md).

Пользовательские типы позволяют дать встроенной семантике собственные названия — например, «Город» для локации — и использовать их при создании, в шаблонах, фильтрах, графе и карточках без копирования сущностей. При связывании двух карточек форма поднимает подходящие предикаты, сохраняя полный ручной выбор. Частые поисковые запросы и фильтры графа можно сохранить как переносимые именованные виды; свободная раскладка карточек при этом остаётся локальной для устройства.

### Прежний технический срез

Создан первый локальный каркас. Он позволяет создать кампанию, сохранить её в IndexedDB браузера, полноценно редактировать сущности, связать их типизированными отношениями и увидеть в Campaign Graph. State Layer хранит изменяемые параметры, Knowledge State отделяет субъективные знания от World Truth, а Condition Builder объединяет проверки состояния, связей, знаний и мирового времени во вложенные группы и применяет последствия только после подтверждения мастера. Session Mode собирает трёхпанельный DM Screen с текущей сценой, участниками, знаниями, правилами, проверками и хронологией. Quick Create сохраняет импровизированные материалы вместе с контекстом в очередь обработки. Базовый Encounter Mode поддерживает стороны, инициативу, HP исходных сущностей, раунды, ходы, эффекты и фиксируемый исход. World Clock переводит время только после предпросмотра запланированных событий и поддерживает пользовательские календари с собственными месяцами, днями недели и эпохой. Завершение сессии предлагает редактируемый Post-Session Summary, собранный из локальной истории. Значимые действия фиксируются в Event Log. Глобальный поиск понимает неверную раскладку и синхронно фильтрует список и граф. Сущности и связи безопасно архивируются, доступны переносимая резервная копия и восстановление кампании. Это рабочий срез MVP, а не готовый продукт.

Trigger Engine проверяет правила после изменений кампании или World Clock, поддерживает задержку в игровом времени и сохраняет срабатывания в мастерской очереди. Автоматическое применение доступно только после явного выбора мастером и защищено ограничением длины цепочки.

Рабочее пространство кампании разделено верхним меню на проведение сессии, подготовку кампании, граф, логику и историю. Одновременно открыт один сценарий, поэтому для перехода между большими блоками не требуется прокручивать всю кампанию.

## Локальный запуск

Требуется Node.js 24 и npm 11 или совместимые версии.

```powershell
npm install
npm run dev
```

Откройте адрес, который покажет локальный сервер (обычно `http://localhost:5173`). Интернет и внешний аккаунт для работы приложения не требуются.

Проверка проекта:

```powershell
npm run check
```

В режиме разработки на главном экране доступна кнопка **«Создать тестовый стенд логики»**. Она создаёт отдельную локальную кампанию с фактами, состояниями и пятью характерными правилами для ручных проверок. Повторное создание требует подтверждения и предварительно сохраняет прежний стенд в локальную страховочную копию; в production-сборке эта команда не показывается.

## Desktop-версия для Windows

Проект содержит Tauri-оболочку и встроенную ручную проверку подписанных обновлений. Для локальной разработки desktop-версии нужны Rust и **Visual Studio Build Tools 2022** с набором **Desktop development with C++** и Windows SDK:

```powershell
npm run desktop:dev
npm run desktop:build
```

Пользователю готового релиза эти инструменты не нужны. Windows-установщик включает автономный WebView2 и устанавливает все необходимые компоненты самостоятельно. Перед первой публикацией необходимо создать ключ подписи обновлений; полная последовательность описана в [desktop-доставке](docs/DESKTOP_DISTRIBUTION.md).

## Структура

- `src/domain` — модель кампании и чистые правила;
- `src/application` — пользовательские сценарии и порты;
- `src/infrastructure` — локальное хранение и будущие адаптеры;
- `src/ui` — русскоязычный интерфейс;
- `src/shared` — общие ресурсы, включая пользовательские строки;
- `docs` — архитектура, дизайн-код, формат данных и принятые решения.

Подробнее: [архитектура](docs/ARCHITECTURE.md), [дизайн-код](docs/DESIGN_SYSTEM.md), [формат данных](docs/DATA_FORMAT.md) и [готовность к следующему релизу](docs/RELEASE_READINESS.md).

Полная продуктовая спецификация и правила разработки находятся в [`Vista_Point_Codex_Project_Guidelines.md`](Vista_Point_Codex_Project_Guidelines.md).

## Резервное копирование и восстановление

1. Откройте кампанию и нажмите **«Скачать резервную копию»**.
2. Храните полученный файл `*.vista-point.json` отдельно от профиля браузера.
3. Для восстановления вернитесь к списку и нажмите **«Импортировать кампанию»**.
4. Файл будет проверен до записи. Если он заменяет существующую кампанию, приложение запросит подтверждение и сначала сохранит текущую версию в IndexedDB.
5. Последнюю локальную страховочную версию можно восстановить из обзора кампании; перед откатом текущее состояние также сохраняется.

## Приватность и данные

Кампании и локальные страховочные копии сохраняются в хранилище текущего браузера и не отправляются в сеть. Очистка данных браузера может удалить и кампании, и локальные копии, поэтому для важных данных необходимо регулярно скачивать внешний файл резервной копии.
